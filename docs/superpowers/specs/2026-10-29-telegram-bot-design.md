# Telegram-бот владельца (этап 2, часть 2) — дизайн

Дата: 2026-10-29
Статус: владелец доверил решения builder'у («сделай по умолчанию, потом скорректируем»).
Основная спека: `docs/superpowers/specs/2026-10-17-ai-chat-design.md`, раздел 8.

## 1. Зачем

Сейчас уведомления приложения (серия неудачных входов, 80/100 % лимита, ошибки OpenRouter, новый
пользователь, удалённый аккаунт) пишутся только в лог (`LogNotifier`). Владелец их не видит. Нужен бот,
который (1) сразу присылает эти алерты владельцу, (2) раз в день и раз в неделю присылает сводку
использования, (3) даёт пару команд, чтобы не ходить в админку ради мелочей.

Успех: владелец узнаёт о важных событиях в течение минуты; утренняя сводка за полминуты отвечает на
«всё ли в порядке и сколько потрачено»; бот не отвечает никому, кроме владельца, и никогда не видит
текста переписки.

## 2. Цели, не-цели, анти-цели

**Цели:** `TelegramNotifier` вместо `LogNotifier`; ежедневная и еженедельная сводки; команды `/help`,
`/stats`, `/users`, `/invite`, `/block <логин>`, `/unblock <логин>`.

**Не-цели:** статус бэкапов в сводке (его уже контролирует Cronitor, а статус-файлы на хосте закрыты
для контейнера приложения); несколько получателей; кнопки/inline-клавиатуры; webhook.

**Анти-цели:** в Telegram попадает текст переписки или заголовки чатов (это тоже содержимое);
бот выполняет команды от кого-то, кроме владельца; токен бота попадает в логи (в URL Telegram API
токен стоит в пути — логирование httpx на уровне INFO его бы выдало); падение Telegram ломает
вход/чат пользователей.

## 3. Решения builder'а (владелец может оспорить)

- Бот живёт **внутри приложения** (`app/telegram/`), без отдельного сервиса и без библиотек для ботов:
  HTTP API Telegram через уже имеющийся `httpx`.
- Входящие команды — **long polling** (`getUpdates`, timeout 30 с) фоновой задачей в lifespan приложения,
  только когда `enable_jobs` и бот настроен. Webhook не нужен (нет нового публичного эндпоинта).
- При старте пропускаются накопившиеся старые сообщения (команды, отправленные, пока приложение
  лежало, не выполняются задним числом — особенно `/block`).
- Настройки: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_CHAT_ID`. Если любое пусто — работает `LogNotifier`,
  бот не запускается (как сейчас). `DIGEST_TIMEZONE` (по умолчанию `Europe/Moscow`) и `DIGEST_TIME`
  (по умолчанию `09:00`).
- Сообщения — **обычный текст** (без Markdown/HTML-разметки), на русском — бот пишет владельцу как
  интерфейс; служебные логи самого бота — на английском (правило проекта).
- Отправка: таймаут 5 с, одна повторная попытка при сетевой ошибке/5xx, 429 — уважать `retry_after`
  (не дольше 30 с). Сбой отправки логируется типом ошибки, без URL; вызывающий код не получает исключение.
- Защита от шквала алертов: не больше 20 алертов в час; лишние отбрасываются, по истечении часа
  приходит одно сообщение «пропущено N уведомлений». Сводки и ответы на команды под лимит не попадают.
- `/invite` создаёт инвайт от имени самого старого активного администратора и присылает ссылку
  (та же функция, что в админке, с аудитом). Ссылка одноразовая, 48 ч.
- `/block` и `/unblock` используют ту же логику, что админка (вынести её в `app/admin/service.py`):
  нельзя блокировать администратора, блокировка отзывает сессии, всё пишется в аудит (`ip = "telegram"`).
- Сообщения не от `TELEGRAM_OWNER_CHAT_ID` игнорируются молча (без ответа), логируется только факт
  и chat id.
- Как узнать chat id: CLI `python -m app.cli telegram-whoami` — читает последние обновления бота и
  печатает chat id отправителей (владелец пишет боту любое сообщение, затем запускает команду).
- Логгер `httpx`/`httpcore` переводится на уровень WARNING, чтобы URL с токеном не попадали в логи.

## 4. Содержимое

**Ежедневная сводка** (каждый день в `DIGEST_TIME` по `DIGEST_TIMEZONE`, за прошедшие календарные сутки
в этом поясе):
```
Сводка за 28.10.2026
Активных пользователей: 3 из 9
Сообщений: 41, новых чатов: 6
Токены: 182 400 (вход 150 100 / выход 32 300)
Расход: $0.84 · с начала месяца $7.12
По пользователям:
  alice — 18 сообщ., $0.41 (месяц $3.10 из $5.00)
  bob — 15 сообщ., $0.30 (месяц $2.02 из $5.00)
  ...
Ошибок модели: 1 · неудачных входов: 4 · новых пользователей: 0
```
Пользователи без активности за сутки не перечисляются. Если активности не было — одна строка
«Сводка за 28.10.2026: активности не было. С начала месяца $7.12».

**Еженедельная сводка** — по понедельникам вместо ежедневной (за прошлую неделю пн–вс): те же цифры
за неделю плюс топ-3 моделей по расходу.

**/stats** — то же, что ежедневная сводка, но за сегодня (с полуночи в `DIGEST_TIMEZONE`) и месяц.
**/users** — все пользователи: логин, активен/заблокирован, расход за месяц / лимит, последняя активность.
**/help** — список команд.

Только метаданные: логины, числа, модели, суммы. Никаких текстов сообщений, заголовков чатов, имён
файлов, IP.

## 5. Ошибки и граничные случаи

- Telegram недоступен / неверный токен — приложение работает как обычно, ошибки в логе (без URL);
  long polling повторяет с паузой (экспоненциально до 60 с).
- Неизвестная команда или неверный логин — короткий ответ «Неизвестная команда, /help» /
  «Пользователь не найден».
- Длинный ответ (>4000 символов) режется на несколько сообщений.
- Сводка не задваивается при перезапуске приложения в момент отправки (допустимо пропустить одну
  сводку, недопустимо — слать много раз).

## 6. Проверка

- Telegram API мокается (respx). Тесты: алерт уходит владельцу; без настроек — LogNotifier; лимит
  20 в час + итоговое сообщение; токен не появляется в логах (caplog) ни при успехе, ни при ошибке;
  команды от чужого chat id игнорируются; `/block`, `/unblock`, `/invite` меняют БД и пишут аудит;
  сводка за сутки считает правильные границы в поясе `Europe/Moscow`; сводка не содержит заголовков
  чатов и текстов (в тестовой БД есть сообщение с уникальной строкой — её нет в тексте сводки);
  длинный ответ режется.
- Владелец: создать бота у BotFather, `telegram-whoami`, прописать два значения в `.env`, `/help`.
