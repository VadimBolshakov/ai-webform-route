# CI на GitHub Actions (этап 2, последняя часть) — дизайн

Дата: 2026-10-29
Статус: одобрено владельцем в чате.

## 1. Зачем

Сейчас все проверки запускаются только локально (`scripts/check.ps1`) и только если о них не забыть.
CI повторяет те же проверки на каждый push и PR на GitHub, чтобы сломанный main был виден сразу.

Успех: зелёная галочка на коммите означает «прошло всё то же, что `scripts/check.ps1`, плюс тест бэкапа».

## 2. Цели, не-цели, анти-цели

**Цели:** `ruff check .`; полный pytest с `-W error` на PostgreSQL 16; `pip-audit`; shellcheck
скриптов бэкапа; bash-тест бэкапа (`tests/test_ops_backup.py::test_backup_scripts`, ~5 мин).

**Не-цели:** деплой на VPS, сборка/публикация Docker-образа, Dependabot, матрица версий Python.

**Анти-цели:** CI требует секретов; тесты в CI тихо пропускаются (например, тест бэкапа без Docker)
и галочка зелёная, хотя ничего не проверено; workflow получает права на запись в репозиторий.

## 3. Решения

- Владелец: пушит нечасто, время до галочки не критично → тест бэкапа на **каждый** push/PR, без nightly.
- Решения builder'а:
  - Один файл `.github/workflows/ci.yml`, триггеры `push` (все ветки), `pull_request`, `workflow_dispatch`.
  - Два параллельных job'а: `checks` (ruff, `pytest -m "not docker"` с сервисом `postgres:16-alpine`, pip-audit,
    shellcheck) и `backup-e2e` (`pytest -m docker`, свой compose-стек, Postgres-сервис не нужен).
    Быстрые ошибки видны через 1–2 мин и отдельно от медленного теста.
  - Тестовая база: `aichat_test`, пользователь/пароль `aichat`/`aichat`,
    `TEST_DATABASE_URL=postgresql+asyncpg://aichat:aichat@127.0.0.1:5432/aichat_test`.
  - В `backup-e2e` `pytest -rs` и проверка, что тест не был пропущен (анти-цель про тихий skip).
  - Actions закреплены по SHA с комментарием-тегом: `actions/checkout` v7.0.1, `actions/setup-python` v7.1.0.
    Python 3.13, `cache: pip` по `pyproject.toml`. shellcheck — образ `koalaman/shellcheck:v0.11.0`,
    как в `scripts/check.ps1`. Postgres — `postgres:16-alpine` (как в `docker-compose.yml`).
  - `permissions: contents: read`; `concurrency` с отменой устаревшего прогона той же ветки.
  - Бейдж CI в README.

## 4. Как проверить

Ветка `ci/github-actions` пушится только с «ок» владельца; владелец смотрит зелёный прогон на GitHub.
Merge в main — тоже только по его слову.
