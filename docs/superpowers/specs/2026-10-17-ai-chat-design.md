# AI-Chat (закрытый) — дизайн

Дата: 2026-10-17
Статус: согласован, ожидает ревью документа

## 1. Цель и рамки

Закрытый веб-сайт для чата с AI-моделями для ~10 приглашённых пользователей (друзья, коллеги).
Некоммерческий. Модели вызываются через OpenRouter API ключом владельца. Использование — только
со стационарных компьютеров (мобильная вёрстка не требуется, но страница не должна ломаться).

Главные требования: защита данных пользователей, контроль расходов, незаметность назначения сайта.

### Этапы

1. **MVP** — приложение целиком (разделы 4–7, 9, 11, включая ширму и скрытый вход); алерты идут
   через интерфейс `Notifier` с реализацией «в лог»; запуск локально в Docker (app + postgres).
2. **Деплой** — VPS, nginx, TLS, бэкапы (раздел 10), Telegram-бот и дайджесты (раздел 8), CI с `pip-audit`.
3. **Расширения** — голосовой ввод (Whisper на сервере), доработки по отзывам.

Каждый этап получает свой план реализации.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Подход | Писать с нуля, не адаптировать Open WebUI / LibreChat |
| Бэкенд | Python, FastAPI, uvicorn |
| Фронтенд | Jinja2 + HTMX + небольшой чистый JS (SSE-стриминг), без npm/сборки |
| БД | PostgreSQL; без Redis (кэш — в памяти приложения) |
| Доступ | Только по одноразовым инвайт-ссылкам (срок 48 ч), открытой регистрации нет |
| 2FA | TOTP: обязательно для админа, по желанию для пользователей |
| Выбор модели | По умолчанию `openrouter/auto` + короткий список разрешённых админом моделей |
| Лимиты | Месячный лимит в $ на пользователя (алерт на 80%, блок на 100%) + жёсткий лимит на ключе OpenRouter |
| Telegram | Только метаданные, без текста переписки; ежедневный и недельный дайджест + срочные алерты |
| Бэкап | Ежедневно, restic → S3-совместимое хранилище (Backblaze B2 / Cloudflare R2), 7д/4н/3м |
| Вложения в MVP | Текст/код, PDF, DOCX, изображения; до 10 МБ; файлы не хранятся |
| Голос | Этап 3, серверное распознавание (Whisper через API) |
| Хостинг | Новый отдельный VPS (2 vCPU / 4 ГБ / 40 ГБ, Ubuntu 24.04, DE); 3X-ui остаётся на старом |
| Домен | `aramistrio.online`, переводится на новый VPS |

## 3. Архитектура

```
Интернет ──443──► nginx (TLS Let's Encrypt, rate-limit, заголовки безопасности)
                    │
                    ├─ /            → статическая страница-«ширма» про AI
                    ├─ /static/*    → CSS/JS (все библиотеки локально, без CDN)
                    └─ /app/*       → FastAPI (127.0.0.1:8000)
                                         │
                ┌────────────────────────┼──────────────────┬───────────────┐
            PostgreSQL              OpenRouter API     Telegram Bot API   Whisper API
         (только внутр. сеть)       (модели, цены)    (отчёты, алерты)   (этап 3)
```

- Запуск: Docker Compose — контейнеры `nginx`, `app`, `postgres`. Порт БД наружу не публикуется.
- Фоновые задачи: APScheduler внутри `app` — дайджесты, проверка лимитов, очистка истёкших
  сессий и инвайтов, суточное обновление списка/цен моделей OpenRouter.
- Бэкап: systemd-таймер на хосте → `pg_dump` → `restic backup` → S3.
- Секреты: `.env` на сервере (права `600`), не в git и не в Dropbox.

### Модули приложения

Каждый модуль — отдельный пакет с узким интерфейсом:

- `auth` — пароли (Argon2id), сессии, TOTP, инвайты, защита от перебора.
- `chat` — чаты и сообщения, сборка контекста, SSE-стриминг.
- `llm` — клиент OpenRouter (стриминг, разбор usage/стоимости, ошибки, список моделей).
- `files` — валидация и извлечение текста из вложений.
- `billing` — учёт расхода, проверка лимитов.
- `notify` — Telegram: отправка дайджестов и алертов, команды бота.
- `admin` — инвайты, пользователи, лимиты, разрешённые модели.
- `web` — маршруты, шаблоны, CSRF, заголовки.

### Ресурсы

Ожидаемая нагрузка при 10 пользователях: 0.8–1.2 ГБ RAM, 3–5 ГБ диска.
VPS 2 vCPU / 4 ГБ / 40 ГБ (~€4–7/мес., например Hetzner CX) — с многолетним запасом.

### Защита сервера

- SSH только по ключу, вход под root запрещён, нестандартный порт.
- ufw: наружу открыты только 80, 443 и порт SSH.
- fail2ban (SSH и вход на сайт), unattended-upgrades.

## 4. Страница-«ширма» и скрытый вход

- `/` — обычная статья/блог об AI без упоминаний входа или чата.
- Вход по пути `/a/<случайная-строка>` (значение задаётся в `.env`); на ширме — неприметная ссылка
  (например, точка в футере).
- Любые пути под `/app` без валидной сессии отвечают **404**, а не редиректом на логин.
- `robots.txt` запрещает индексацию приватных путей; заголовок `X-Robots-Tag: noindex` на них.

## 5. Модель данных (PostgreSQL)

| Таблица | Поля / назначение |
|---|---|
| `users` | логин, хеш пароля (Argon2id), роль `admin`/`user`, секрет TOTP (зашифрован), месячный лимит $, настройки (язык ответа, тема, системный промпт, модель по умолчанию), дата согласия с политикой, `is_active`, даты |
| `invites` | хеш токена, создатель, `expires_at`, `used_by`, `used_at` |
| `auth_sessions` | хеш ID сессии, пользователь, `expires_at` (7 дней, скользящий), IP, User-Agent, `last_seen` |
| `chats` | владелец, заголовок, `pinned`, `created_at`, `updated_at` |
| `messages` | чат, роль `user`/`assistant`, текст, вложения (имя + извлечённый текст), фактическая модель, флаг «прервано», `created_at` |
| `usage` | пользователь, чат, модель, prompt/completion токены, стоимость $ (из ответа OpenRouter), задержка, статус/ошибка, `created_at` |
| `models_allowed` | id модели OpenRouter, отображаемое имя, `enabled`, поддержка изображений |
| `audit_log` | тип события, пользователь, IP, детали, `created_at` |

Правила:

- Стоимость берётся из usage в ответе OpenRouter, а не вычисляется; лимит считается по ней.
- Удаление аккаунта: каскадно удаляются чаты, сообщения, сессии; в `usage` и `audit_log`
  пользователь обезличивается (`deleted-user-<id>`).
- Удалённые данные сохраняются в бэкапах до 3 месяцев (ротация) — отражено в политике.
- Admin технически имеет доступ к серверу и БД; политика честно это указывает. Сквозное шифрование
  невозможно, так как текст передаётся в OpenRouter.

### Политика конфиденциальности

Показывается при регистрации по инвайту, согласие (галочка) обязательно. Содержит: какие данные
хранятся, что запросы уходят в OpenRouter и далее провайдерам моделей, что админ получает только
статистику, сроки хранения (включая бэкапы), как удалить аккаунт и экспортировать данные.
В настройках ключа OpenRouter запрещается использование запросов для обучения.

## 6. Интерфейс

```
┌──────────────┬──────────────────────────────────────────────┐
│ [+ Новый чат]│   Ответы модели (Markdown, подсветка кода,   │
│ Последние 10 │   «копировать» у блоков кода)                │
│ • Чат 1   📌 │   под ответом: модель · токены · $ · [💾]    │
│ [Все чаты…]  ├──────────────────────────────────────────────┤
│ 👤 vadim  ▾  │ [+] [ Поле ввода ] [🎤 — этап 3] [Стоп]      │
│              │ Модель: [Auto ▾]   Расход: $1.20 / $5.00     │
└──────────────┴──────────────────────────────────────────────┘
```

- Боковая панель: последние 10 чатов; «Все чаты» — список с поиском по заголовкам;
  действия с чатом: переименовать, закрепить, удалить. Заголовок генерируется дешёвой моделью.
- Под каждым ответом: фактическая модель, токены, стоимость, сохранение ответа в `.md`/`.txt`
  (на стороне браузера). Также доступно сохранение всего чата.
- Enter — отправить, Shift+Enter — перенос строки; кнопка «Стоп» прерывает генерацию.
- Меню пользователя: язык ответа (RU/EN), тема (светлая/тёмная/системная), свой системный промпт,
  модель по умолчанию, смена пароля, 2FA, активные устройства + «выйти везде», расход за месяц,
  экспорт своих данных (JSON), удаление аккаунта (с подтверждением паролем), выход.
- Админ-раздел: создание инвайтов, пользователи и их расход, изменение лимита,
  блокировка/разблокировка, управление списком моделей.

## 7. Поток запроса

1. POST (текст, файлы, CSRF-токен) → проверка сессии, rate-limit (20 запросов/мин на пользователя),
   месячного лимита.
2. Вложения: PDF → pypdf, DOCX → python-docx, текстовые — как есть (проверка кодировки);
   изображения — проверка через Pillow, перекодирование (удаление метаданных), передача base64.
   Если выбранная модель не поддерживает изображения — понятная ошибка.
3. Контекст: системный промпт (язык ответа + пользовательский промпт) + история чата,
   обрезанная по бюджету токенов (последние сообщения).
4. Запрос в OpenRouter со `stream: true`; ответ транслируется в браузер по SSE.
5. По завершении: сохранение сообщения, модели, токенов, стоимости; при пересечении 80%/100%
   лимита — алерт в Telegram.

### Ошибки

- Таймаут / 429 / 5xx от OpenRouter → понятное сообщение и кнопка «Повторить»; запись в `usage`
  со статусом ошибки; серия ошибок → алерт в Telegram.
- Оборванный стрим → сохраняется полученная часть с пометкой «прервано».
- Ошибка разбора файла → сообщение пользователю, запрос не отправляется.

## 8. Telegram

- Бот реагирует только на `chat_id` владельца, остальные апдейты игнорируются.
- Ежедневный дайджест: по каждому пользователю — число сессий/сообщений, модели, токены, $;
  итог за день и с начала месяца; статус ночного бэкапа. По воскресеньям — недельная сводка.
- Срочные алерты: неудачные входы (серия), блокировки, 80%/100% лимита, ошибки OpenRouter
  (серия), сбой бэкапа или его проверки.
- Команды: `/stats`, `/invite` (создать инвайт), `/block <user>`, `/unblock <user>`.
- Текст переписки в Telegram не передаётся никогда.

## 9. Безопасность приложения

- Пароли: Argon2id, минимум 10 символов, проверка по локальному списку утёкших паролей.
- Перебор: блокировка с растущей задержкой после 5 неудач + rate-limit nginx + fail2ban.
- Cookie сессии: `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict`; ротация ID после входа и смены пароля.
- CSRF-токен для всех форм и HTMX-запросов.
- XSS: автоэкранирование Jinja2, Markdown ответа — через DOMPurify; строгий CSP без внешних источников.
- Заголовки: HSTS, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`.
- Файлы: ≤10 МБ, тип по содержимому, обработка в памяти с таймаутом, на диск не пишутся.
- Секреты только в `.env` на сервере; жёсткий лимит расходов на ключе OpenRouter.
- Зависимости закреплены по версиям; `pip-audit` в CI.

## 10. Бэкапы

- Ежедневно в 03:30: `pg_dump` → `restic backup` → S3 (Backblaze B2 / Cloudflare R2).
- Ротация: 7 дневных, 4 недельных, 3 месячных.
- Ключ доступа к хранилищу с сервера — append-only; очистка старых снапшотов (`restic forget --prune`)
  выполняется владельцем со своего компьютера.
- Ежемесячно — автоматическое тестовое восстановление во временную БД с проверкой.
- Пароль репозитория restic хранится у владельца отдельно (менеджер паролей).
- Результат — в дайджесте, сбой — срочным алертом.

## 11. Тестирование

- pytest + тестовая PostgreSQL в Docker; OpenRouter и Telegram — моки.
- Покрытие: авторизация, инвайты, 2FA, лимиты, изоляция пользователей (нет доступа к чужим чатам),
  CSRF, удаление аккаунта и обезличивание, учёт стоимости, обработка ошибок OpenRouter,
  извлечение текста из файлов.
- Перед запуском: чек-лист безопасности, проверка Mozilla Observatory и SSL Labs.

## 12. Вне рамок (YAGNI)

Мобильная вёрстка, открытая регистрация, оплата, Redis, RAG/хранение файлов, генерация изображений,
многоязычный интерфейс сайта (интерфейс на русском; язык выбирается только для ответов модели).
